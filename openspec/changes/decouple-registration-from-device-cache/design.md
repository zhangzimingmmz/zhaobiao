## Context

当前小程序在注册成功或登录被审核状态拦截后，会把 `applicationId`、`username`、`mobile` 保存到设备本地；注册页加载时又会主动读取这些缓存并调用审核状态接口。结果是注册入口被“上一次在这台手机上提交过谁”主导，而不是由当前用户主动决定要注册哪个账号。

这个问题主要影响两个场景：
- 同一台手机需要连续注册多个账号时，注册页会短暂出现后自动跳到审核状态页或登录页。
- 用户尚未登录时，系统却先基于设备缓存判断账号审核状态，造成“注册流程属于设备而不是账号”的错觉。

现有后端登录后分流能力已经存在：登录成功后会根据账号状态跳转到首页、审核状态页或重新提交资料页。因此本次调整不需要新增后端接口，而是把审核状态判断职责收回到登录后阶段。

## Goals / Non-Goals

**Goals:**
- 让注册页始终表现为“新建注册入口”，进入时不再因为设备缓存自动跳转。
- 保留登录成功后的账号状态分流，让 pending/rejected/approved 都在“确认账号身份之后”再处理。
- 允许同一台手机连续发起多个账号的注册，不被本地注册上下文锁死。
- 将本地注册上下文缩减为一次性反馈用途，而不是长期驱动注册页入口。

**Non-Goals:**
- 不修改后端“一个账号/手机号对应一个注册主体”的业务约束。
- 不新增短信、邮箱或新的审核状态接口。
- 不重做审核状态页本身的视觉结构，只调整入口与触发时机。

## Decisions

### 1. 注册页不再自动读取本地申请上下文并查询审核状态
注册页加载时 SHALL 直接展示空白或当前正在填写的注册表单，不再基于 `registrationApplicationId` 等本地缓存自动调用审核状态接口。

原因：
- 注册入口应该服务“我要新注册一个账号”，而不是“恢复这台手机上次提交的申请”。
- 设备缓存不具备用户身份语义，会误伤多账号场景。

备选方案：
- 保留自动查询，但增加“继续这次申请 / 重新开始注册”选择弹窗。
  - 未采用，因为它仍然让设备缓存成为注册页入口的第一决策者，用户第一次看到的不是表单而是状态拦截。

### 2. 登录成功后继续作为唯一的账号状态分流入口
用户点击登录并通过凭证校验后，系统继续调用“当前用户状态”接口，根据该账号当前状态决定：
- `approved` -> 进入首页
- `pending` -> 进入审核状态页
- `rejected` / `none` -> 进入注册页或资料修正页

原因：
- 审核状态是账号属性，不是设备属性。
- 登录后分流天然已经知道“当前是谁”，判断更准确，也更符合用户预期。

备选方案：
- 在注册页和登录页都查询审核状态。
  - 未采用，因为职责重复，会继续制造入口不一致和状态冲突。

### 3. 本地注册上下文只保留短期反馈用途，并在关键时机清理
注册成功后可以短期保留必要上下文，用于当次流程的审核状态跳转或提示；但一旦用户进入登录成功路径或明确离开该次注册流程，应清理这份本地上下文，避免它长期影响后续注册入口。

原因：
- 完全去掉上下文会丢失“注册成功后跳审核状态页”的衔接便利。
- 但长期保留又会导致用户后续再进注册页时被历史状态劫持。

备选方案：
- 完全保留现有上下文直到用户手动清理。
  - 未采用，因为这正是当前问题来源。

## Risks / Trade-offs

- [Risk] 用户注册成功后，如果离开了审核状态页，后续无法再靠注册页自动恢复上次申请进度。
  → Mitigation：保留登录后分流和“我的/审核状态页”入口，让状态查询回归账号维度。

- [Risk] 清理本地注册上下文过早，可能打断“注册成功后立即查看审核状态”的连续性。
  → Mitigation：仅在登录成功或明确结束该次流程后清理，不影响当次注册完成后的引导。

- [Risk] 现有文案和页面提示如果不一起调整，用户可能不理解为什么注册页不再自动跳走。
  → Mitigation：补充注册成功提示文案，明确告知“请登录查看审核状态”或“可前往审核状态页查看”。

## Migration Plan

1. 修改小程序注册页，移除页面加载时基于本地注册上下文自动查询审核状态的逻辑。
2. 保留注册提交成功后的即时反馈与跳转，但调整本地上下文的使用范围和清理时机。
3. 复核登录成功后的状态分流逻辑，确保 pending/rejected/approved 仍能正确进入对应页面。
4. 回归验证同一设备连续注册不同账号、已审核通过账号再次登录、被驳回账号重新提交流程。

回滚策略：
- 如果新逻辑造成注册后状态衔接断裂，可回滚到原先的注册页自动恢复逻辑。
- 回滚只涉及小程序前端代码，不影响后端数据结构。

## Open Questions

- 注册成功后是否仍然自动跳审核状态页，还是统一回登录页并提示“登录后查看审核状态”。
- 被驳回用户登录后应直接进入注册页编辑，还是先进入审核状态页查看驳回原因后再进入注册页。
